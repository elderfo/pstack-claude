# CONTEXT — domain glossary

Names for the concepts this repo's design discussions keep reaching for. Architecture reviews use these terms; if a review needs a concept that isn't here, add it.

- **Build** — one of the runtimes the plugin ships to: the Claude Code build (`.claude-plugin/`), the Codex build (`.codex-plugin/`), the Pi build (the root `package.json` `pi` block plus `.pi-plugin/`), and the native Agent Skills paths for Prime Agent, opencode, and Gemini CLI (`~/.agents/skills/` symlinks). All builds share one `skills/` tree. Runtime-specific execution adapters stay separate from discovery.
- **Agent Skill** — one directory under `plugins/pstack/skills/` with portable `name` and `description` frontmatter. Codex, Pi, Prime Agent, opencode, and Gemini CLI discover this shared tree natively. Runtime-specific keys may affect visibility only where that runtime understands them.
- **Model policy** — the mapping from roles to symbolic model profiles, resolved through the active runtime adapter. Model identity, effort and fresh/fork context are separate choices. Defaults live in `plugins/pstack/models.json` and are stamped into each skill's Models section; the user's override sheet, written by `setup-pstack`, is the layer that adapts them at runtime. Its path is runtime-specific: `~/.claude/pstack-models.md` on Claude Code, `~/.codex/pstack-models.md` on Codex, `~/.pi/agent/pstack-models.md` on Pi.
- **Role** — a named unit of delegated work with its own model choice (`arena runners`, `how critics`, `swarm workers`). The role vocabulary lives in `models.json` and surfaces in `setup-pstack`'s sheet.
- **Panel** — the three-model diverse panel the multi-model skills (`arena`, `architect`, `interrogate`, `how`) run by default. One fact in `models.json`; the generator stamps every copy and fails on strays.
- **Prompt stub** (or trampoline) — a generated file whose body invokes its skill, one per public skill per runtime that has a command surface of its own: `.codex-plugin/prompts/` for Codex, `.pi-plugin/prompts/` for Pi. Both render from the skill's `menu-description`. Every other supported runtime discovers the shared Agent Skill directly.
- **Menu description** — the `menu-description:` frontmatter one-liner every public skill carries. Renders as the Codex slash-menu text, the Pi prompt-template description, and the README command-table row; the long `description:` stays the trigger-matching prose.
- **Runtime adapter** — a `references/<runtime>-tools.md` file implementing the capabilities in `runtime-contract.md` with concrete native tools, registered profiles, model/effort lowering, context, scoped transcripts and permissions. Claude, Codex and Pi each own their adapter; discovery is not an execution guarantee.
- **Mandate** — the routing text injected at session start that sends non-trivial engineering work into `poteto-mode`. One copy per runtime that can inject it: `hooks/session-start-context.md` for Claude Code, `.pi-plugin/session-start-context.md` for Pi. The wording differs per runtime, so a change to the routing is a change to both files.
- **Generator** — `tools/generate.mjs`. Stamps facts from their single source into every committed copy and validates cross-file contracts. CI reruns it and fails on any diff.
- **Generator-owned copy** — a committed value the generator writes (the `version` field in the four manifests, the prompt stubs and Pi agent definitions, the README slash-command table, every Models section). Hand edits are reverted by the next regeneration and caught by CI.
- **VERSION** — the repo-root file holding the canonical plugin version. Releases edit it, add the matching `CHANGES.md` heading, and regenerate; plugin auto-update installs by this number.
- **Sync boundary** — the split between what upstream pstack owns (skill content) and what this port owns (Cursor-to-Claude-Code translation). Defined in [CONTRIBUTING.md](CONTRIBUTING.md); enforced by `tools/sync.mjs`, whose substitution table and denylist live in `tools/substitutions.json`.
- **Upstream pin** — the per-component upstream SHA in `tools/upstream.json` that the port is synced to. `sync.mjs` advances it only when a sync completes without denylist hits.
- **Invariant script** — `tests/skill-collision-repro.sh`. The repo's check seam: static layout/flag invariants (one named function each, run through `check`) plus a behavioral leg that needs the `claude` CLI. `tests/invariants.test.mjs` proves each static check can fail, against fixture trees.
